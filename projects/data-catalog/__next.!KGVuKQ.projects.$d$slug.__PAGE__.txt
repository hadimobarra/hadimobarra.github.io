b:T6fd,<h2 id="the-problem">The problem</h2>
<p>In a large organization, people lose time working out which dataset exists, what its columns mean, who owns it and whether they are allowed to use it. The catalog is where those questions get answered.</p>
<h2 id="what-i-built">What I built</h2>
<p><strong>Discovery.</strong> A searchable catalog for finding, tagging and governing datasets.</p>
<p><strong>Mapping Table and Mapping Column.</strong> Interfaces, inspired by Databricks, that let people define relationships between entities visually.</p>
<p><strong>Role management.</strong> A module with dynamic, fine-grained access-control rules. It replaced a static permission model, so admins can manage access themselves.</p>
<p><strong>Glossary approval.</strong> A review and approval workflow that enforces governance policies and keeps a full audit trail.</p>
<p><strong>Two languages.</strong> Full Persian (RTL) localization with i18next, and a metadata schema extended to hold both Persian and English values.</p>
<h2 id="decisions-that-mattered">Decisions that mattered</h2>
<p><strong>Permissions belong in data, not in components.</strong> Once rules are dynamic, hard-coded role checks become bugs waiting to happen. The interface asks what the current user can do and renders from that answer.</p>
<p><strong>RTL is a layout concern, not a translation step.</strong> Logical properties (<code>margin-inline-start</code> rather than <code>margin-left</code>) let one set of styles serve both directions. Technical content such as column names, SQL and file paths stays left-to-right inside a right-to-left page.</p>
