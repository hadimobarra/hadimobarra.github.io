9:Taea,<h2 id="the-problem">The problem</h2>
<p>The previous version looked fine and scored badly. Every section was a client component, so visitors downloaded an animation library, an i18n library and both languages' texts before anything could move. Much of the page started at <code>opacity: 0</code> and stayed invisible until scripts ran. Persian existed only in browser memory: no URL, nothing for search engines, and the choice was lost on reload.</p>
<h2 id="decisions">Decisions</h2>
<p><strong>Two real languages.</strong> English lives at the root and Persian under <code>/fa/</code>, each with its own root layout, so <code>lang</code>, <code>dir</code> and <code>hreflang</code> are right in the HTML. The translation library is gone: dictionaries are read while the pages are built, and a missing key is a type error.</p>
<p><strong>CSS instead of an animation library.</strong> Reveals use scroll-driven animations (<code>animation-timeline: view()</code>). Where those aren't supported, the content is simply there. One delegated listener drives every pointer glow.</p>
<p><strong>Islands only where there is state.</strong> The header, search, contact form, blog filter and table of contents are client components. The command menu and the upload demo load on first use.</p>
<p><strong>Fonts that can't shift the layout.</strong> The framework's font loader made each page preload both languages' fonts, about 110 KB. The fonts are now self-hosted and each page preloads only its own. My first fix dropped preloading altogether; Lighthouse in CI failed it, because text moved when the font arrived on machines without a matching fallback. <code>font-display: optional</code> rules that out.</p>
<p><strong>Checks in CI.</strong> Every deploy has to pass type checks, a JavaScript budget, Playwright tests, axe in light and dark themes, link and metadata checks, and Lighthouse.</p>
