9:Tde9,<h2 id="the-problem">The problem</h2>
<p>On Safari, "Download as image" in Apache Superset produced a blank or partial file. It affected charts and whole dashboards, in every WebKit-based browser. The issue had been open since May 2024.</p>
<h2 id="root-cause">Root cause</h2>
<p>Superset captures a chart with <code>dom-to-image-more</code>. That library clones the DOM node, wraps the clone in an SVG <code>&#x3C;foreignObject></code>, and paints the SVG to a canvas. WebKit applies a stricter security model to <code>&#x3C;foreignObject></code> and refuses to paint it, so the canvas stays empty. The library documents Safari as unsupported for this reason, which meant no option or workaround inside it would help.</p>
<h2 id="constraints">Constraints</h2>
<ul>
<li><strong>Chrome and Firefox had to stay identical.</strong> Their pipeline carries special handling for ag-grid print layout and high-resolution ECharts output.</li>
<li><strong>No extra weight for everyone else.</strong> A second rasterizer is only useful on one engine.</li>
<li><strong>Superset renders many kinds of charts.</strong> DOM tables, 2D canvases and WebGL maps each fail in a different way when captured.</li>
</ul>
<h2 id="decisions">Decisions</h2>
<p><strong>Swap the rasterizer, only on Safari.</strong> <code>html2canvas</code> reads the DOM and paints it to a canvas itself, so it never needs <code>&#x3C;foreignObject></code>. It was already in the dependency tree through <code>dom-to-pdf</code>, so the change promoted it to a direct dependency. Replacing the capture path for all browsers would have put working exports at risk.</p>
<p><strong>Load it lazily.</strong> The library is imported inside the Safari branch, so it stays out of the core bundle.</p>
<p><strong>Keep the table lifecycle.</strong> My first version returned early and skipped the ag-grid print layout, which would have cut off virtualized rows. The final version keeps that lifecycle and replaces only the last step.</p>
<p><strong>Measure after expanding.</strong> Clipped content is expanded in the clone, so dimensions taken from the live element were too small. The capture now updates its size in <code>onclone</code>, from the expanded clone.</p>
<p><strong>Preserve WebGL buffers.</strong> A WebGL canvas reads back blank unless its drawing buffer is preserved. Mapbox and MapLibre now set that on Safari. deck.gl drew its layers into a separate canvas of its own, so on Safari its overlays use interleaved mode and share the base map's context.</p>
<p><strong>Accept one limit.</strong> Images from servers without CORS headers are left out. Allowing a tainted canvas would make the whole export fail instead.</p>
<h2 id="review-and-result">Review and result</h2>
<p>Two reviewers from the project went through several rounds, and their questions about WebGL and table truncation made it clearly better. It merged on 1 October 2026: 8 files, 553 lines added and 48 removed, with most of the additions being tests.</p>
<h2 id="what-i-would-do-differently">What I would do differently</h2>
<p>I don't have a Mac, and jsdom can't render WebGL. The tests prove the configuration is passed through; they can't prove the pixels are right. Before merge, a reviewer with real Safari found that interleaved mode exposed a version mismatch between two deck.gl packages in the lockfile. Superset's main branch has since moved both to the same version, but that shows the gap: for rendering work I would now arrange a real-device check before opening the PR, rather than leaving it to
