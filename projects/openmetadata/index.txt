2b:T8ea,<h2 id="context">Context</h2>
<p>OpenMetadata is an open-source platform for data discovery, quality and governance. At Adin I build on a fork of version 1.7.0. I also contribute upstream.</p>
<h2 id="on-the-fork">On the fork</h2>
<p><strong>ETL pipeline editor.</strong> Built from scratch: a structured canvas for composing ingestion stages, with a live YAML preview next to it. People who prefer a visual editor and people who prefer configuration files work on the same pipeline.</p>
<p><strong>Schema translation tooling.</strong> Many OpenMetadata forms are generated from JSON Schema, so their labels don't come from ordinary translation files. I built i18n tooling that translates the schema-driven labels too.</p>
<p><strong>Persian and RTL.</strong> Full right-to-left localization, including fixes for layout and state bugs on entity and pipeline pages.</p>
<h2 id="upstream-malformed-diffs-no-longer-crash-the-page">Upstream: malformed diffs no longer crash the page</h2>
<h3 id="problem">Problem</h3>
<p>Entity version pages show what changed between versions. The values are stored as JSON strings, and the UI called <code>JSON.parse()</code> on them while rendering. One malformed or oddly shaped value was enough to crash the page.</p>
<h3 id="change">Change</h3>
<ul>
<li>Shared safe parsers with shape validation for diff arrays and objects. Invalid entries fall back to empty values while valid ones still render.</li>
<li>Applied to tags, owners, domains, table constraints, schemas, pipelines, ML features and search-index fields.</li>
<li>Nested <code>children</code> are validated recursively, because a bad payload could otherwise reach a recursive renderer.</li>
</ul>
<h3 id="bugs-found-along-the-way">Bugs found along the way</h3>
<p>Writing tests for the parsers exposed two correctness bugs that had nothing to do with crashes:</p>
<ul>
<li>Added and deleted search-index fields never appeared, because the lookup used the key for tasks instead of fields.</li>
<li>ML feature changes were paired by position. Filtering could shift the positions, so they are now paired by name.</li>
</ul>
