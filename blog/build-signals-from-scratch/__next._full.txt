29:T4a20,<h2 id="why-signals-are-everywhere">Why signals are everywhere</h2>
<p>Solid, Preact Signals, Angular, Vue, Svelte 5 runes and the TC39 Signals proposal all share one idea: <strong>track exactly which computations read which values, and re-run only those when a value changes.</strong> Instead of re-rendering a component tree and diffing, a signal-based UI updates the one text node that depends on the changed value.</p>
<p>The best way to understand it is to build one. We'll write <code>signal</code>, <code>computed</code> and <code>effect</code> in plain JavaScript.</p>

<p>The effect depends on <code>a</code> twice (through <code>b</code> and <code>c</code>). That intermediate state is called a <strong>glitch</strong>.</p>
<p>The fix used by real libraries is two-phase propagation: first <strong>mark</strong> everything downstream as stale, then <strong>run</strong> effects once, after the write completes. A simple version uses a queue and a batch depth:</p>

    <span class="hljs-title function_">fn</span>();

    batchDepth--;
    <span class="hljs-keyword">if</span> (batchDepth === <span class="hljs-number">0</span>) <span class="hljs-title function_">flush</span>();
  }

  <span class="hljs-keyword">for</span> (<span class="hljs-keyword">const</span> run <span class="hljs-keyword">of</span> [...pendingEffects]) {
    pendingEffects.<span class="hljs-title function_">delete</span>(run);

<p>The JSX compiler in Solid wraps each dynamic expression in an effect, which is why only the text node that reads a signal updates when it changes — components run exactly once.</p>
<h2 id="trade-offs-worth-knowing">Trade-offs worth knowing</h2>
<ul>
<li><strong>Memory:</strong> every dependency edge is a <code>Set</code> entry. Large graphs need cleanup on disposal or they leak.</li>
<li><strong>Debuggability:</strong> implicit tracking is convenient but can hide why something re-ran. Good devtools matter.</li>
<li><strong>Equality:</strong> <code>Object.is</code> means mutating an object in place won't notify. Treat signal values as immutable, or use a custom equality function.</li>
</ul>
