<p>Static export is a great fit for content sites. These are the things that surprised me.</p>
<h2 id="1-metadata-is-replaced-not-merged">1. Metadata is replaced, not merged</h2>
<p>A layout sets a default social image. A page sets its own title for sharing:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-ts"><span class="hljs-keyword">export</span> <span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">generateMetadata</span>(<span class="hljs-params"></span>) {
  <span class="hljs-keyword">return</span> {
    <span class="hljs-attr">openGraph</span>: { <span class="hljs-attr">title</span>: <span class="hljs-string">"My article"</span>, <span class="hljs-attr">type</span>: <span class="hljs-string">"article"</span> },

}
</code></pre><span class="code-lang code-title">app/blog/[slug]/page.tsx</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>The page now has <em>no</em> image. Next.js merges metadata shallowly: the page's <code>openGraph</code> object <a href="https://nextjs.org/docs/app/api-reference/functions/generate-metadata#merging">replaces</a> the layout's. The same goes for <code>alternates</code>, so one article-specific canonical URL also removed the RSS link from every article here. Nothing warns you, and the page looks perfect until someone shares it.</p>
<p>The inverse hurts too. Pages that <em>don't</em> set <code>alternates</code> inherit it. The blog index was telling search engines that its canonical URL was the homepage.</p>

</ul>

<h2 id="6-check-what-your-bundler-merges">6. Check what your bundler merges</h2>
<p>I used <code>next/font</code> in both layouts, one font per language. The build merged their CSS into one chunk, and preloading works per chunk. Every English page preloaded the Persian fonts, and the other way around.</p>
<p>Nothing in the code looked wrong. The network panel showed it immediately. I ended up hosting the fonts myself, with an explicit preload per language. The <a href="/blog/less-javascript-same-blocking-time/">longer version</a> includes the wrong fix I tried first.</p>
