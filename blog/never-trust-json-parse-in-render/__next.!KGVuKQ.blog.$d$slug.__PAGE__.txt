15:Tf94,<h2 id="one-bad-string-one-dead-page">One bad string, one dead page</h2>
<p>OpenMetadata keeps a history of every entity. A version page shows what changed between two versions: tags added, owners removed, a column renamed. Each change stores its old and new values as JSON <em>strings</em>, and the interface parsed them while rendering:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-ts"><span class="hljs-keyword">const</span> <span class="hljs-attr">oldTags</span>: <span class="hljs-title class_">TagLabel</span>[] = <span class="hljs-title class_">JSON</span>.<span class="hljs-title function_">parse</span>(<span class="hljs-title function_">getChangedEntityOldValue</span>(diff) ?? <span class="hljs-string">'[]'</span>);
</code></pre><span class="code-lang">ts</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>That line contains two promises nobody can keep. It promises that the string is valid JSON, and it promises that the JSON is an array of tags. If either fails, the exception happens during render, and React unmounts the tree. The user sees an error page because of one row written long ago.</p>
<p>My fix was merged as <a href="https://github.com/open-metadata/OpenMetadata/pull/33580">pull request #33580</a>.</p>
<h2 id="the-type-annotation-is-the-trap">The type annotation is the trap</h2>
<p><code>JSON.parse</code> returns <code>any</code>. Assigning <code>any</code> to <code>TagLabel[]</code> compiles without a complaint, so the annotation looks like a check and isn't one. It's a comment the compiler believes.</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-ts"><span class="hljs-keyword">const</span> <span class="hljs-attr">tags</span>: <span class="hljs-title class_">TagLabel</span>[] = <span class="hljs-title class_">JSON</span>.<span class="hljs-title function_">parse</span>(<span class="hljs-string">'{"oops": true}'</span>); <span class="hljs-comment">// compiles</span>
tags.<span class="hljs-title function_">map</span>(<span class="hljs-function">(<span class="hljs-params">t</span>) =></span> t.<span class="hljs-property">tagFQN</span>); <span class="hljs-comment">// TypeError at runtime</span>
</code></pre><span class="code-lang">ts</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>The honest return type is <code>unknown</code>. It makes the compiler ask the question you were skipping:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-ts"><span class="line"><span class="hljs-keyword">const</span> <span class="hljs-attr">parsed</span>: <span class="hljs-built_in">unknown</span> = <span class="hljs-title class_">JSON</span>.<span class="hljs-title function_">parse</span>(value);

<h3 id="why-not-a-schema-library">Why not a schema library?</h3>
<p>In a new project I would reach for <a href="https://zod.dev/">Zod</a> or <a href="https://valibot.dev/">Valibot</a>: you get the type and the check from one definition. In someone else's large codebase, a bug fix that adds a dependency is a harder conversation than one that adds sixty lines. Match the tool to the change.</p>

<h2 id="do-error-boundaries-solve-this">Do error boundaries solve this?</h2>
<p>They help with a different part. An <a href="https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary">error boundary</a> turns a blank page into a message, and you should have one. But it can only replace a whole subtree. It can't show the four good tags and skip the bad one. Validation decides what's shown; the boundary is for what you didn't foresee.</p>
<h2 id="checklist">Checklist</h2>
<ol>
<li>Search the codebase for <code>JSON.parse(</code> inside components and the functions they call.</li>
<li>Replace <code>any</code> with <code>unknown</code> at each one.</li>
<li>Decide per place: drop the item, use a default, or stop.</li>
<li>Write the test with the malformed value first, and watch it crash.</li>
<li>Include <code>null</code>, an object where an array is expected, and a nested bad child.</li>
</ol>

<p>Anything that comes from storage, a network or <code>localStorage</code> was written by some other version of your software. Parse it as if a stranger wrote it.
