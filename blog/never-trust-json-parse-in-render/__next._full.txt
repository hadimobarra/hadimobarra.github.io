<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-ts"><span class="hljs-keyword">const</span> <span class="hljs-attr">oldTags</span>: <span class="hljs-title class_">TagLabel</span>[] = <span class="hljs-title class_">JSON</span>.<span class="hljs-title function_">parse</span>(<span class="hljs-title function_">getChangedEntityOldValue</span>(diff) ?? <span class="hljs-string">'[]'</span>);

<h3 id="why-not-a-schema-library">Why not a schema library?</h3>
<p>In a new project I would reach for <a href="https://zod.dev/">Zod</a> or <a href="https://valibot.dev/">Valibot</a>: you get the type and the check from one definition. In someone else's large codebase, a bug fix that adds a dependency is a harder conversation than one that adds sixty lines. Match the tool to the change.</p>
<h2 id="the-bugs-the-tests-found">The bugs the tests found</h2>

<p><strong>A lookup with the wrong key.</strong> Added and deleted search-index fields never appeared on the version page. The code asked for the diff of <code>tasks</code> where it needed <code>fields</code>:</p>

<h2 id="do-error-boundaries-solve-this">Do error boundaries solve this?</h2>
<p>They help with a different part. An <a href="https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary">error boundary</a> turns a blank page into a message, and you should have one. But it can only replace a whole subtree. It can't show the four good tags and skip the bad one. Validation decides what's shown; the boundary is for what you didn't foresee.</p>
<h2 id="checklist">Checklist</h2>
<ol>
<li>Search the codebase for <code>JSON.parse(</code> inside components and the functions they call.</li>
<li>Replace <code>any</code> with <code>unknown</code> at each one.</li>
<li>Decide per place: drop the item, use a default, or stop.</li>
<li>Write the test with the malformed value first, and watch it crash.</li>
<li>Include <code>null</code>, an object where an array is expected, and a nested bad child.</li>
</ol>

<p>Anything that comes from storage, a network or <code>localStorage</code> was written by some other version of your software. Parse it as if a stranger wrote it.
