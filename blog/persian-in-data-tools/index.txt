35:T1021,<h2 id="two-tools-one-question">Two tools, one question</h2>
<p>More than two billion people use Arabic-script languages, according to <a href="https://kclpure.kcl.ac.uk/ws/files/383439862/2026_VIS_RTL_Interviews_tools_revised_-2.pdf">a recent study of chart tools</a>. It tested seven tools, and none of them was Apache Superset or OpenMetadata, the two I contribute to. So I ran both in Persian, with a small Persian dataset, and measured what happened. The <a href="/rtl/">report card</a> has every result and screenshot.</p>
<h2 id="the-layout-doesnt-turn-around">The layout doesn't turn around</h2>
<p>After switching to Persian, neither Superset 6.1.0 nor OpenMetadata 1.12.14 set a direction on the page. The navigation stayed on the left. Every Persian text sat in a left-to-right container, which shows in small ways: the full stop moves to the wrong end of a sentence, and a long title loses its <em>first</em> letters instead of its last.</p>
<p>This is known. Superset's <a href="https://github.com/apache/superset/issues/25258">RTL issue</a> is closed as mostly done, and a <a href="https://github.com/apache/superset/pull/34629">pull request</a> that aimed to finish it was closed unmerged after the theme code it depended on had changed several times. OpenMetadata fixed a <a href="https://github.com/open-metadata/OpenMetadata/issues/37397">direction regression</a> this month, after the version I tested.</p>
<h2 id="translated-isnt-the-same-as-correct">Translated isn't the same as correct</h2>
<p>Superset's Persian file has 5,957 entries. 2,473 of them are marked <em>fuzzy</em>, which means unreviewed: 1,569 come from a machine translation that says so in a comment, and 904 were guessed from similar sentences. Release 6.1.0 includes fuzzy entries when it builds translations. The guesses can be far off:</p>

<h2 id="a-language-code-that-may-explain-a-mystery">A language code that may explain a mystery</h2>
<p>OpenMetadata's Persian file contains Spanish ("Acción requerida"), Portuguese ("Salvar alterações"), Turkish, Pashto, Arabic and, in a few places, pirate English:</p>
<blockquote>
<p>Shiver me timbers! Error fetchin' the treasures…</p>
</blockquote>
<p>These are checked against the file as it was on 24 November 2026. The file is called <code>pr-pr.json</code>. The code for Persian is <code>fa</code>. My guess, and it is a guess, is that tools filling in missing strings read <code>pr-PR</code> as Puerto Rico, as Portuguese, or as pirate. Of its 7,243 entries, 188 contain no Persian, and 322 are identical to English.</p>
<h2 id="how-to-check-your-own-project">How to check your own project</h2>
<ol>
<li><strong>Use standard codes.</strong> <code>fa</code>, <code>ar</code>, <code>he</code>. Tools make decisions based on them.</li>
<li><strong>Set <code>lang</code> and <code>dir</code> on the document</strong> when the language changes.</li>
<li><strong>Look for one translation shared by several sources.</strong> In Superset, that found 461 entries worth reading.</li>
<li><strong>Check the script.</strong> A Persian file should contain Persian letters.</li>
<li><strong>Don't ship what's marked unreviewed</strong>, or show which strings are.</li>
</ol>
<p>The <a href="https://github.com/hadimobarra/my-space-/tree/main/rtl-report">scripts</a> need only Python and a browser.</p>
<h2 id="what-this-is-not">What this is not</h2>
<p>It's a pilot: two tools, desktop only, default settings, no keyboard or screen reader testing. Both projects are free, and both have accepted fixes from me.
