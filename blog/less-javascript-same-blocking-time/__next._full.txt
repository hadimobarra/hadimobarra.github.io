<p>The previous version of this site shipped 282 KB of gzipped JavaScript on the homepage. Every section was a client component, because each used an animation library and an i18n library. The plan was obvious: move to server components, animate with CSS, ship less.</p>

<h2 id="what-was-removed">What was removed</h2>
<ul>
<li><strong>The animation library.</strong> Reveal effects are now <a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll-driven_animations">scroll-driven CSS animations</a>.</li>
<li><strong>The translation runtime.</strong> Text is resolved while the page is built.</li>
<li><strong>State and toast libraries.</strong> What was left needed <code>useState</code>.</li>
<li><strong>Hydration of static sections.</strong> Cards and lists are plain HTML.</li>
</ul>

<h2 id="why-blocking-time-stayed">Why blocking time stayed</h2>
<p>Total Blocking Time adds up the part of each long task beyond 50 ms. It doesn't care how many kilobytes were sent, only how long the main thread was busy at a stretch. So I profiled a local build with a four-times CPU slowdown.</p>
<p>The first suspects were decorative: large blurs, backdrop filters, a noise texture, endless animations. I switched each off in turn and measured again:</p>

<p>The long tasks were these:</p>
<ol>
<li><strong>The first style and layout of a long page.</strong> Nine sections with many cards is a big tree.</li>
<li><strong>Starting React and hydrating.</strong> This is mostly the framework's own cost, and it's the same with two islands or twelve.</li>

<blockquote>
<p>Bytes and blocking are different budgets. Removing code buys you download and parse time. It buys main-thread time only if that code was in the long tasks.</p>
</blockquote>
<h2 id="the-font-mistake">The font mistake</h2>
<p>Along the way I found that every page preloaded the fonts of both languages, about 110 KB. The bundler had merged the CSS of two layouts. I turned preloading off, and my scores went up:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-ts"><span class="hljs-keyword">const</span> sans = <span class="hljs-title class_">Geist</span>({ <span class="hljs-attr">subsets</span>: [<span class="hljs-string">"latin"</span>], <span class="hljs-attr">preload</span>: <span class="hljs-literal">false</span> });
</code></pre><span class="code-lang">ts</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>Then Lighthouse failed in CI, with a layout shift of 0.14 on a site that had none on my machine. The size-adjusted fallback is based on Arial. My machine has a match for it; the CI runner evidently doesn't, and neither does an Android phone. There, the text moved when the real font arrived.</p>
<p>The real fix was to host the fonts myself, preload only the page's own language, and use <code>font-display: optional</code>, which never swaps after the first paint. Layout shift went back to zero, and stayed there.</p>
<p>Loosening the check would have been one number in a config file. It would also have shipped a regression to every phone without that font.</p>

<h2 id="what-i-would-do-next">What I would do next</h2>
<ul>
<li><strong>Delay hydration</strong> of islands far below the fold, since starting the framework is what remains.</li>
<li><strong>Measure real users.</strong> Lab numbers on one laptop swing widely: eight runs of the same page gave 280 to 700 ms.</li>
</ul>
<h2 id="what-id-tell-someone-starting-the-same-work">What I'd tell someone starting the same work</h2>
<ol>
<li>Write down the metric you expect to move, before you change anything.</li>
<li>Profile first. I removed the right code for LCP and not the code behind TBT.</li>
<li>Run each measurement several times and publish the range. A single good run is an anecdote.</li>
<li>Keep the check that embarrasses you.</li>
</ol>
