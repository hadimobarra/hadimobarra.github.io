f:T69c,<h2 id="the-usual-mistake">The usual mistake</h2>
<p>A product is finished in English. Then someone asks for Persian or Arabic, so the strings go to a translator and a <code>dir="rtl"</code> goes on the page. Half of the layout flips, the other half doesn't, and file paths read backwards.</p>
<p>I led the Persian localization of a data platform, and this site is bilingual too. The lesson from both is the same: translation changes words, while direction changes layout. They are different jobs.</p>
<h2 id="write-direction-neutral-css-from-the-start">Write direction-neutral CSS from the start</h2>
<p>Physical properties name sides of the screen. Logical properties name sides of the <em>text</em>. Only one of them survives a direction change.</p>
<div class="table-wrap" tabindex="0"><table>

<td><code>padding-right</code></td>
<td><code>padding-inline-end</code></td>
</tr>

</tr>

</tr>

<h2 id="text-has-its-own-direction">Text has its own direction</h2>
<p>The Unicode <a href="https://www.unicode.org/reports/tr9/">bidirectional algorithm</a> decides the order of mixed text. Letters have a strong direction. Punctuation, spaces and slashes are neutral and take their direction from their neighbours. That's why a path like <code>/data/2026/report (final).csv</code> falls apart inside a Persian sentence: its slashes and brackets get adopted by the Persian text around them.</p>
<p>The fix is isolation. Tell the algorithm that a run of text is an island:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-html"><span class="hljs-comment">&#x3C;!-- direction known --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">bdi</span> <span class="hljs-attr">dir</span>=<span class="hljs-string">"ltr"</span>></span>/data/2026/report (final).csv<span class="hljs-tag">&#x3C;/<span class="hljs-name">bdi</span>></span>

<span class="hljs-comment">&#x3C;!-- direction unknown: user names, titles, search terms --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">bdi</span>></span>{userName}<span class="hljs-tag">&#x3C;/<span class="hljs-name">bdi</span>></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">p</span> <span class="hljs-attr">dir</span>=<span class="hljs-string">"auto"</span>></span>{comment}<span class="hljs-tag">&#x3C;/<span class="hljs-name">p</span>></span>
</code></pre><span class="code-lang">html</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>In a data product, isolate these by default: column names, SQL, file paths, URLs, email addresses, versions and keyboard shortcuts. Code blocks and terminals stay left-to-right inside a right-to-left page. Set <code>dir="ltr"</code> on them.</p>
<p>For form fields, <code>dir="auto"</code> follows whatever the user types. An email field should be <code>dir="ltr"</code> always, even when its label is Persian.</p>

<p>A direction variant keeps this in one place:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-css"><span class="hljs-selector-attr">[dir=<span class="hljs-string">"rtl"</span>]</span> <span class="hljs-selector-class">.icon-directional</span> {
  <span class="hljs-attribute">transform</span>: <span class="hljs-built_in">scaleX</span>(-<span class="hljs-number">1</span>);
}
</code></pre><span class="code-lang">css</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>Use <code>scaleX(-1)</code> rather than <code>rotate(180deg)</code> for anything asymmetric. A rotated paper-plane icon is upside down.</p>
<h2 id="transforms-dont-know-about-direction">Transforms don't know about direction</h2>
<p>Logical properties cover layout, not transforms. <code>translateX(20px)</code> moves right in every language, so a drawer that slides in from the start needs a sign:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-css"><span class="hljs-selector-class">.drawer</span> { <span class="hljs-attr">--dir</span>: <span class="hljs-number">1</span>; <span class="hljs-attribute">transform</span>: <span class="hljs-built_in">translateX</span>(<span class="hljs-built_in">calc</span>(-<span class="hljs-number">100%</span> * <span class="hljs-built_in">var</span>(--dir))); }
<span class="hljs-selector-attr">[dir=<span class="hljs-string">"rtl"</span>]</span> <span class="hljs-selector-class">.drawer</span> { <span class="hljs-attr">--dir</span>: -<span class="hljs-number">1</span>; }
</code></pre><span class="code-lang">css</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>The same goes for scroll positions in JavaScript. In RTL containers <code>scrollLeft</code> starts at 0 and becomes <em>negative</em>. Carousel code with <code>scrollLeft += width</code> needs the same sign.</p>
<h2 id="fonts-and-spacing">Fonts and spacing</h2>
<p>Persian and Arabic letters join. Negative letter-spacing, popular for large headings, breaks the joins and looks like a rendering bug. On this site one rule prevents it:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-css"><span class="hljs-selector-tag">html</span><span class="hljs-selector-attr">[lang=<span class="hljs-string">"fa"</span>]</span> <span class="hljs-selector-tag">body</span> *<span class="hljs-selector-pseudo">:not</span>(<span class="hljs-selector-pseudo">:lang</span>(en))<span class="hljs-selector-pseudo">:not</span>(<span class="hljs-selector-attr">[dir=<span class="hljs-string">"ltr"</span>]</span>) {
  <span class="hljs-attribute">letter-spacing</span>: <span class="hljs-number">0</span> <span class="hljs-meta">!important</span>;
}
</code></pre><span class="code-lang">css</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>Also check line height. Arabic-script letters have tall marks and deep descenders, and a heading set at <code>line-height: 1</code> will clip them. <code>text-transform: uppercase</code> does nothing in these scripts, so a design that relies on capitals for hierarchy needs another signal.</p>
<h2 id="numbers-dates-and-plurals">Numbers, dates and plurals</h2>
<p>Digits are a locale choice. Let the platform make it:</p>
<div class="code-block" dir="ltr"><pre tabindex="0"><code class="hljs language-js"><span class="hljs-keyword">new</span> <span class="hljs-title class_">Intl</span>.<span class="hljs-title class_">NumberFormat</span>(<span class="hljs-string">"fa-IR"</span>).<span class="hljs-title function_">format</span>(<span class="hljs-number">15859</span>);  <span class="hljs-comment">// ۱۵٬۸۵۹</span>
<span class="hljs-keyword">new</span> <span class="hljs-title class_">Intl</span>.<span class="hljs-title class_">DateTimeFormat</span>(<span class="hljs-string">"fa-IR"</span>).<span class="hljs-title function_">format</span>(date); <span class="hljs-comment">// Solar Hijri calendar</span>
</code></pre><span class="code-lang">js</span><button type="button" class="code-copy" data-copy-code="" aria-label="Copy code"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><rect x="9" y="9" width="13" height="13" rx="2"></rect><path d="M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"></path></svg></button></div>
<p>Decide where <em>not</em> to localize. Identifiers, version numbers and code should keep Latin digits, because people copy them.</p>
<p>Never assemble sentences from fragments. <code>"Page " + n + " of " + total</code> can't be reordered by a translator. Use one string with placeholders.</p>
<h2 id="test-it-like-a-layout-not-like-a-translation">Test it like a layout, not like a translation</h2>
<ul>
<li><strong>Screenshots in both directions</strong> for each component. Most bugs are visible at a glance.</li>
<li><strong>Pseudo-RTL in English.</strong> Set <code>dir="rtl"</code> on the English build. You find layout bugs before any translation exists.</li>
<li><strong>Mixed content.</strong> Test with a Persian sentence that contains a path, a number and an English product name.</li>
<li><strong>Keyboard.</strong> In a right-to-left tab list, the left arrow goes to the next tab.</li>
</ul>
<p>On this site, the same automated tests check pages in both languages for horizontal overflow and accessibility problems.</p>
<h2 id="conclusion">Conclusion</h2>
<p>If the layout is written in terms of start and end, RTL is mostly a configuration value. If it's written in terms of left and right, RTL is a rewrite. The choice is made long before anyone asks for a second language.</p>
