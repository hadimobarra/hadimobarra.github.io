پشتیبانی RTL یک استایل آینه‌ای نیست که آخر کار اضافه شود. ویژگی‌های منطقی، جداسازی متن، آیکون‌ها، فونت و اعداد: کدام بخش رابط باید تغییر جهت بدهد و کدام نباید.

راست‌به‌چپ مرحله‌ای از ترجمه نیست

اشتباه رایج

محصول به انگلیسی کامل می‌شود. بعد کسی نسخه فارسی یا عربی می‌خواهد؛ متن‌ها به مترجم سپرده می‌شوند و یک dir="rtl" به صفحه اضافه می‌شود. نیمی از چیدمان برمی‌گردد، نیمی دیگر نه، و مسیر فایل‌ها به‌هم‌ریخته دیده می‌شود.

من بومی‌سازی فارسی یک پلتفرم داده را رهبری کرده‌ام و این سایت هم دوزبانه است. درس هر دو یکی است: ترجمه کلمات را عوض می‌کند و جهت، چیدمان را. این‌ها دو کار جدا هستند.

از ابتدا CSS مستقل از جهت بنویسید

ویژگی‌های فیزیکی از لبه‌های صفحه نام می‌برند و ویژگی‌های منطقی از ابتدا و انتهای متن. فقط دومی با تغییر جهت درست می‌ماند.

فیزیکی منطقی
margin-left margin-inline-start
padding-right padding-inline-end
border-left border-inline-start
left: 0 inset-inline-start: 0
text-align: left text-align: start

Flexbox و Grid خودشان از جهت پیروی می‌کنند. بیشتر چیدمان‌های خراب از یک margin فیزیکی درون ظرفی منطقی می‌آیند.

امتحان کنید: جهت را عوض کنید و دو شیوه را مقایسه کنید.

فیزیکی یا منطقی؟

فایل /data/2026/report (final).csv آماده است!
border-left: 4px solid;
padding-left: 16px;
margin-right: 12px;

پیش‌نمایش راست‌به‌چپ و با ویژگی‌های فیزیکی شروع می‌شود. ویژگی‌های منطقی را انتخاب کنید و به فاصله آیکون، لبه رنگی و فلش نگاه کنید.

در Tailwind معادل آن‌ها ms-*، me-*، ps-*، pe-*، start-* و end-* است. یک قانون lint علیه نسخه فیزیکی، از تذکر در هر بازبینی کد ارزان‌تر است.

متن جهت خودش را دارد

الگوریتم دوجهته یونیکد ترتیب متن‌های ترکیبی را تعیین می‌کند. حروف جهت قطعی دارند. نشانه‌گذاری، فاصله و ممیز خنثی هستند و جهت را از همسایه می‌گیرند. برای همین مسیری مثل /data/2026/report (final).csv وسط جمله فارسی به‌هم می‌ریزد.

راه‌حل، جداسازی است. به الگوریتم بگویید این تکه یک جزیره است:

<!-- جهت مشخص است -->
<bdi dir="ltr">/data/2026/report (final).csv</bdi>

<!-- جهت نامشخص است: نام کاربر، عنوان، عبارت جست‌وجو -->
<bdi>{userName}</bdi>
<p dir="auto">{comment}</p>
html

در محصول داده‌محور این موارد را پیش‌فرض جدا کنید: نام ستون، SQL، مسیر فایل، URL، ایمیل، شماره نسخه و میان‌بر صفحه‌کلید. بلوک کد و ترمینال در صفحه راست‌به‌چپ هم باید چپ‌به‌راست بمانند.

برای فیلد ورودی، dir="auto" از نوشته کاربر پیروی می‌کند. فیلد ایمیل همیشه dir="ltr" است، حتی با برچسب فارسی.

همه چیز آینه نمی‌شود

آینه شود آینه نشود
فلش قبلی و بعدی پخش و مکث
جداکننده مسیر صفحه ساعت و پیشرفت دایره‌ای
نوار پیشرفت و اسلایدر لوگو
تورفتگی و نمای درختی نمودار زمانی (از کاربر بپرسید)
آیکون ارسال تیک و ذره‌بین

یک متغیر جهت این موضوع را یک‌جا نگه می‌دارد:

[dir="rtl"] .icon-directional {
  transform: scaleX(-1);
}
css

برای شکل‌های نامتقارن از scaleX(-1) استفاده کنید، نه rotate(180deg). هواپیمای کاغذی چرخیده، وارونه می‌شود.

transform از جهت خبر ندارد

ویژگی‌های منطقی چیدمان را پوشش می‌دهند، نه transform را. translateX(20px) در همه زبان‌ها به راست می‌رود؛ پس کشویی که از ابتدا وارد می‌شود به علامت نیاز دارد:

.drawer { --dir: 1; transform: translateX(calc(-100% * var(--dir))); }
[dir="rtl"] .drawer { --dir: -1; }
css

در جاوااسکریپت هم scrollLeft در ظرف راست‌به‌چپ از صفر شروع و منفی می‌شود.

فونت و فاصله‌ها

حروف فارسی به هم می‌چسبند. فاصله منفی بین حروف که در تیترهای بزرگ رایج است، اتصال را می‌شکند. در این سایت یک قانون جلوی آن را می‌گیرد:

html[lang="fa"] body *:not(:lang(en)):not([dir="ltr"]) {
  letter-spacing: 0 !important;
}
css

ارتفاع خط را هم بررسی کنید. خط فارسی نقطه‌ها و دنباله‌های بلند دارد و تیتری با line-height: 1 بریده می‌شود. همچنین text-transform: uppercase در فارسی اثری ندارد؛ اگر طراحی برای سلسله‌مراتب به حروف بزرگ تکیه کرده، نشانه دیگری لازم است.

عدد، تاریخ و جمله

شکل ارقام به زبان بستگی دارد. آن را به پلتفرم بسپارید:

new Intl.NumberFormat("fa-IR").format(15859);  // ۱۵٬۸۵۹
new Intl.DateTimeFormat("fa-IR").format(date); // تقویم خورشیدی
js

مشخص کنید کجا بومی‌سازی نشود. شناسه، شماره نسخه و کد باید رقم لاتین بمانند، چون کپی می‌شوند.

جمله را از تکه‌ها نسازید. مترجم نمی‌تواند ترتیب "Page " + n + " of " + total را عوض کند. یک رشته با جای‌نگهدار بنویسید.

مثل چیدمان آزمایش کنید، نه مثل ترجمه

  • اسکرین‌شات هر کامپوننت در دو جهت. بیشتر باگ‌ها با یک نگاه دیده می‌شوند.
  • RTL ساختگی روی نسخه انگلیسی. با dir="rtl" روی نسخه انگلیسی، باگ‌های چیدمان پیش از هر ترجمه‌ای پیدا می‌شوند.
  • محتوای ترکیبی. جمله فارسی همراه مسیر فایل، عدد و نام انگلیسی را امتحان کنید.
  • صفحه‌کلید. در فهرست زبانه‌های راست‌به‌چپ، فلش چپ به زبانه بعدی می‌رود.

جمع‌بندی

اگر چیدمان با ابتدا و انتها نوشته شود، RTL تقریباً یک تنظیم است. اگر با چپ و راست نوشته شود، RTL یک بازنویسی است. این انتخاب خیلی پیش از آنکه کسی زبان دوم بخواهد انجام می‌شود.

برای مطالعه بیشتر: ویژگی‌های منطقی در MDN و راهنمای W3C درباره متن دوجهته.
